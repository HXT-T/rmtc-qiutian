# 检录与录屏清单

依据规则 §2.2 / §2.4：须在比赛设备与指定有线网络上完成编译启动、接收本队感知、回填正确 tick 与 session_id、
提交合法动作并取得执行回执；第二阶段还需真实统一 AI 调用。运行截图或录屏于 **2026-10-31 20:00 前**随其他材料递交。
令牌全程隐藏输入，录屏中不得出现令牌、模型 Key 或其他凭据。

## 0. 准备（录屏前）

- [ ] 比赛设备：Ubuntu 22.04 + ROS 2 Humble；`python3 -m rmtc_bot doctor` 显示 rclpy、std_msgs 可用。
- [ ] 代码为冻结版本 freeze-1029：`training_lab/contestant`（提交代码仓库，不提交镜像）。
- [ ] `python3 -m unittest discover -s tests -t . -q` 全部通过（93 项）。
- [ ] 已拿到主办方通知：席位、ROS 域编号、AI 网关完整地址（`/v1/chat/completions`）、本场令牌（模型一律使用统一默认模型，不设置 `RMTC_AI_MODEL`）。
- [ ] 有线网络已接入；`ROS_LOCALHOST_ONLY=0`。

## 1. 录屏内容（按顺序）

| 步骤 | 操作 | 画面中要能看到 |
|---|---|---|
| 1 | `source /opt/ros/humble/setup.bash`，设置 `ROS_LOCALHOST_ONLY=0`、`RMW_IMPLEMENTATION=rmw_fastrtps_cpp`、`RMTC_AI_URL` | 环境变量（不含令牌） |
| 2 | `read -rsp '本场席位令牌: ' RMTC_TEAM_TOKEN; echo; export RMTC_TEAM_TOKEN` | 只出现提示文字，令牌不回显 |
| 3 | `bash scripts/run_contestant.sh --stage 2 --team 席位 --domain-id 域 --name '秋天' --config config/default.json --decision-config config/decision_config.json --log logs/checkin.jsonl` | 启动日志 `Ready: /team_X; waiting for perception and referee start` |
| 4 | 裁判开始联调后等待约 30 Tick | 终端无异常；裁判端显示本队动作与执行回执 |
| 5 | 另开终端：`python3 -m rmtc_bot analyze logs/checkin.jsonl` | 见下方验收字段 |
| 6 | 第一阶段（如联调）：`--stage 1 --team A`，同样执行步骤 3–5 | `decisions`、`receipts` 增长，`invalid_actions` 为 0 |

## 2. 验收字段（`analyze` 输出）

- `session_id` 与裁判公布的本场一致；`team` 为本场席位。
- `decisions` 与 `receipts` 均大于 0 且接近（回执证明动作被执行，仅收到感知不能证明双向通信）。
- `receipt_errors` 为空，`invalid_actions` 为 0，`controller_faults` 为 0，`perception_rejections` 为 0。
- 第二阶段：`http_successes ≥ 1`（真实统一 AI 服务成功调用）；正式资格以裁判记录为准，`formal_ai_eligibility` 字段只作提示。
- `planning_max_ms` 远低于节拍（第一阶段 100 ms、第二阶段 500 ms）。

## 3. 提交内容

规则 v1.2：10 月 31 日 20:00 前递交**代码仓库**与**技术报告（语雀文档）**，不提交镜像。

- 代码仓库：`training_lab/contestant` 目录（冻结版本 freeze-1029），须完整可运行；比赛时启动的代码路径与版本必须与仓库一致。

## 4. 换场与重启

- 换场或拿到新令牌：结束进程，重新执行步骤 2–3（日志出现 `token_refresh_required` 时必须重启）。
- 程序异常：登记后重启封存版本（每阶段原则上最多 2 次），同场重启会按感知自动恢复。
