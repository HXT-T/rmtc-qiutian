## 2. 验收字段（`analyze` 输出）

- `session_id` 与裁判公布的本场一致；`team` 为本场席位。
- `decisions` 与 `receipts` 均大于 0 且接近（回执证明动作被执行，仅收到感知不能证明双向通信）。
- `receipt_errors` 为空，`invalid_actions` 为 0，`controller_faults` 为 0，`perception_rejections` 为 0。
- 第二阶段：`http_successes ≥ 1`（真实统一 AI 服务成功调用）；正式资格以裁判记录为准，`formal_ai_eligibility` 字段只作提示。
- `planning_max_ms` 远低于节拍（第一阶段 100 ms、第二阶段 500 ms）。

## 4. 比赛当天

- 第一阶段在裁判开赛前启动好程序；第二阶段每场有约 3 分钟准备，按接入单更新席位、ROS 域、网关地址、令牌。
- 第二阶段每场至少要有一次真实 AI 成功调用，否则任务分为 0；程序第 0 Tick 就会调用，用 `analyze` 的 `http_successes` 核对。
- 工作人员会检查 git 状态：在克隆目录运行，不要留下未提交的修改（日志已被 `.gitignore` 排除）。
- 申诉由队长在本场结束后 5 分钟内提出，保留 `logs/` 日志，提交时遮挡令牌。

## 5. 换场与重启

- 换场或拿到新令牌：结束进程，重新执行步骤 2–3（日志出现 `token_refresh_required` 时必须重启）。
- 程序异常：登记后重启封存版本（每阶段原则上最多 2 次），同场重启会按感知自动恢复。
