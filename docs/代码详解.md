# 代码详解（参赛程序 `rmtc_bot`）

适用版本：`training_lab/contestant`（封存候选 perf11-adopted 及其后的默认等价修改）。运行方法见 [README](../README.md)，
设计依据与实验证据见 [技术报告](技术报告.md) 与 `training_lab/docs/algorithm-iterations.md`。

## 1. 总览

```text
rmtc_bot/
  __main__.py   命令行：run / replay / analyze / doctor
  ros_node.py   ROS 2 适配：订阅感知与公告，发布动作与注册
  protocol.py   感知解析与校验（Frame），动作构造
  engine.py     每 Tick 的决策主循环与战术选择
  planner.py    地图记忆、寻路、目标选择（束搜索）
  events.py     LLM 事件计划的校验与事件效果查询（EventBook）
  ai.py         统一 AI 网关客户端（后台线程，单在途）
  scoring.py    v1.1 有效伤害与对抗分算术
  policies.py   四种登记的决策类型
  audit.py      异步 JSONL 审计日志与赛后分析
  config.py     全部可封存参数（Config）
```

只依赖 Python 标准库；ROS 端用 `rclpy` 和 `std_msgs/String`（JSON 文本）。策略只使用本队合法感知、公开公告和自身记忆，
从不读取裁判真值、全图或其他队数据。

## 2. 一个 Tick 的数据流

```text
/team_X/perception ──► ros_node.on_frame ──► Engine.step(raw)
                                               1. Frame.parse：字段类型、坐标、场次、Tick 校验
                                               2. 旧 Tick / 已退役场次 → 丢弃；同 Tick 重发 → 返回缓存动作
                                               3. 新场次 → 重建记忆、AI 代次、事件簿
                                               4. 记录回执（last_action），失败的移动目标短暂避让
                                               5. 新公告 → AIWorker.request（异步，不阻塞本 Tick）
                                               6. _poll_ai：取回已完成的 AI 结果 → validate_plan → EventBook.merge
                                               7. WorldMemory.update：可见区域刷新资源/障碍/敌人
                                               8. Planner.route：选目标与第一步方向
                                               9. Engine._choose：攻击 / 防御 / 移动 / 等待 打分取最大
                                              10. 审计日志（动作、原因、规划耗时、分数）
                                   ◄── 动作 JSON ──┘
ros_node 发布 /team_X/action（回填本帧 tick 与 session_id）
```

最终帧（tick = 总 Tick）只读取回执与分数，不再发布动作。

## 3. 各模块

### 3.1 `__main__.py`

- `run`：正式运行（`--contest` 严格模式：必须显式 ROS 域；第二阶段必须有网关与令牌）。读取 `--config`（只允许 `Config` 已有字段）
  和 `--decision-config`（只允许 `decision_type`）。
- `replay`：从 JSONL 感知离线回放，不发 HTTP/ROS 请求，用于回归测试与调试。
- `analyze`：读审计日志，输出每场决策数、回执数、无效动作、AI 成功数、规划耗时等（检录用）。
- `doctor`：只读环境检查。

### 3.2 `ros_node.py`

| 方向 | 话题 | QoS |
|---|---|---|
| 订阅 | `/team_X/perception` | 可靠、volatile、深度 1 |
| 订阅 | `/referee/event_text`、`/referee/team_registry`、`/referee/mission` | 可靠、transient-local |
| 发布 | `/team_X/action` | 可靠、volatile、深度 1 |
| 发布 | `/team_X/registration`（队名） | transient-local |

### 3.3 `protocol.py`

`Frame.parse` 把感知解码为结构化帧：9×9 相对视野字符串逐实体还原成绝对坐标（x 向右、y 向下），校验 HP、分数、任务等字段的类型与范围；
不合法的感知被拒绝（记 `perception_rejections`），不会推进策略。`action()` 生成带 tick 与 session_id 的动作。

### 3.4 `planner.py`

- **WorldMemory**：`seen`（见过的格子，只增不减）、障碍、资源（含最后看见的 Tick）、敌人最近目击、访问次数、短期避让格。
  可见区域里消失的资源与障碍会被清除；世界分裂结束后撤销期间观察到的临时墙。
- **distances**：Dijkstra。未见格可通行但加 0.15 代价；只有存在分裂/爆炸事件时才逐边查事件（否则跳过，结果相同）；
  无时间相关事件时按地形缓存距离表；邻居表按地图尺寸预计算。
- **route**（目标选择）：
  1. 即将生效的爆炸或分裂会波及当前位置时，先撤离；
  2. 候选目标：已知资源（封顶前后的增量收益 × 陈旧度 × 竞速系数）、到达任务、事件机会（回血点、堡垒）、
     **未探索区域**（`explore_value`：规则资源数 ÷ 地图格数 × 平均价值 × 0.25 × 前沿新视野格数，Tick 150 前线性衰减）；
  3. 第一阶段若可全部巡回，用最近邻 + 2-opt 巡回；否则做宽度 `beam_width`、深度 `beam_depth` 的束搜索，按“折扣收益 ÷ 行程”评分；
  4. 无目标时：接近可见敌人 → 调查最近目击 → 前沿探索 → 巡逻久未观察的区域。
- `_mission_bonus`：资源类任务（普通、高价值、资源总价值）的进度奖励。
- `_unseen_counter`：二维前缀和，O(1) 查询某格周围视野内的未见格数。

### 3.5 `engine.py`

- `step`：见第 2 节。
- `_choose`：枚举候选动作并打分。
  - 攻击：按目标防御概率估计实际伤害（扣除 HP 上限溢出），加击杀奖励份额（与同线其他攻击者平分），考虑易伤倍率、反伤、无双攻击；
  - 防御：减少的预期受伤；
  - 移动：沿路线方向的收益（路线效用）、拾取资源、辣椒点、下一 Tick 风险与环境伤害；
  - 风险项 `survival_loss`：预期受伤 × 生存权重（按决策类型），会致死时再加死亡扣分对有效伤害的边际损失。
- `_incoming` / `_targets`：基于可见敌人的位置、防御状态与无双效果估计受击和可攻击目标；最近的车辆会遮挡后方攻击。

### 3.6 `events.py`

- `validate_event` / `validate_plan`：模型输出逐事件校验（8 种事件、绝对 Tick 区间、坐标在图内、矩形有序、参数白名单）；
  `partial=True` 时保留合格事件、返回不合格原因。
- `EventBook`：合并已接受事件，并回答规划需要的问题——某格某 Tick 是否被十字墙阻挡（`blocked`）、移动是否反向（`inverted`）、
  是否易伤（`vulnerable`）、是否已获无双（`fortress_power`）、环境伤害（`hazard`）、可利用的事件目标（`opportunities`）。
- 程序本身不解析公告文本（规则禁止关键词/正则解析），只消费模型输出。

### 3.7 `ai.py`

- `AIWorker.request`：公告或任务文本变化时发起请求；同一席位只有一个在途请求；新公告不受旧失败退避影响，
  同一公告的重试按指数退避（最多 `ai_max_digest_attempts` 次）。
- `_run`（后台线程）：POST `/v1/chat/completions`（非流式、`max_tokens`、不带 `model`（统一默认模型）、JSON 模式）；不读系统代理、不跟随重定向；
  日志不记录令牌与异常字符串。网关以 400/422 拒绝 JSON 模式时，本进程自动改用普通请求。
- 配额：401/404/`quota_exceeded` 后停用；换场重置代次，旧场次的迟到结果被丢弃。

### 3.8 `scoring.py` 与 `policies.py`

- `after_tick` / `marginal_value`：v1.1 有效伤害逐 Tick 结算（先加伤害与击杀奖励，再扣死亡，最低 0；500 封顶只影响分数不截断数值）。
- 四种决策类型 balanced / collect / combat / survive 只改变伤害与生存的权重；balanced 允许采纳模型的倾向建议。

### 3.9 `audit.py`

异步写 JSONL，记录 `registry`、`session`、`decision`（动作、原因、位置、HP、规划耗时、分数）、`receipt`、`ai_result`、`ai_plan`、
`ai_partial`、`ai_discarded`、`token_refresh_required` 等。`analyze()` 汇总为检录字段。

## 4. 配置参数（`Config`）

| 参数 | 默认 | 说明 / 状态 |
|---|---|---|
| `stage`、`team`、`name`、`total_ticks` | 启动参数 | 阶段、席位、队名、总 Tick（0 = 规则默认 100/500） |
| `decision_type` | balanced | 现场唯一可切换项 |
| `attack_damage`、`defended_damage`、`attack_range`、`resource_cap`、`damage_cap`、`kill_reward`、`death_penalty` | 20/10/2/120/500/60/60 | 规则公布数值 |
| `resource_count`、`resource_total` | 16 / 200 | 规则公布资源总量（探索价值先验） |
| `beam_width`、`beam_depth` | 20 / 4 | 束搜索规模 |
| `explore_weight` | 1.0 | 已采用（全新地图 SPRT 通过，+5.59） |
| `ai_json_mode` | true | JSON 输出模式，带自动回退 |
| `ai_timeout`、`ai_max_inflight` | 6 s / 1 | 慢模型时可现场前改为 20 s / 2（需按封存流程） |
| `ai_relative_time` | false | 未采用 |
| `ai_min_interval`、`ai_max_tokens`、`ai_max_calls`、`ai_max_attempts`、`ai_max_digest_attempts`、`ai_max_age` | 1 s / 1024 / 0 / 0 / 3 / 40 | 请求节流、上限与结果有效期 |

## 5. 安全修改代码

1. 行为改动一律加开关、默认保持原行为。
2. 每次修改后在 `training_lab` 运行 `python -m lab.regress`：两套单元测试 + 9 条第二阶段回放 + 48 张第一阶段模拟图，决策须与基准版本逐字段一致，
   且源码不得含 CRLF。
3. 行为改动按预先登记的批次测试（筛选 → 500 ms 比赛场景确认）通过后，才改默认值并更新 `regression/reference.json`。
