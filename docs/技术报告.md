# 秋天 · RMTC 技术报告

> 队伍、分工与现场记录见第 9 节，须由队员按真实情况填写。本报告其余数字均来自本地官方 v1.1 练习裁判的可复现实验记录，
> 不是正式比赛成绩；练习中的 AI 调用不构成正式 AI 资格。

## 1. 目标与约束

规则 v1.1：第一阶段 20×20、100 Tick、100 ms/Tick，单车采集，满分 40；第二阶段 24×24、500 Tick、500 ms/Tick，四队对抗，
得分 = 0.25·min(资源价值,120) + 5·任务数 + 15·min(有效伤害,500)/500（满分 60，已用 392 条官方结果核对无误差）。
随机事件只以自然语言公告发布，必须经主办方统一 AI 服务由大语言模型理解，禁止关键词或正则解析。

## 2. 架构

```text
/team_X/perception ──► Frame.parse（字段与场次/Tick 校验）──► WorldMemory（只记本队合法感知）
                                                          │
           /referee/event_text ─► AIWorker（单在途 HTTP 线程）─► validate_plan ─► EventBook
                                                          ▼
                                        Planner.route（Dijkstra + 束搜索选目标）
                                                          ▼
                                 Engine._choose（攻击/防御/移动/等待的即时收益比较）──► /team_X/action
                                                          │
                                                   AuditLog（异步 JSONL 审计）
```

- `protocol.py` 解析 9×9 相对视野；地图坐标 x 向右、y 向下；每帧以 `self.position` 为准。
- `engine.py` 处理 Tick/场次：旧 Tick 与已退役场次丢弃，同 Tick 重发返回缓存动作，换场重建记忆与 AI 代次。
- `ai.py` 不发布动作、不改规划状态，只把经校验的事件计划交给规划器；AI 不可用时本地采集、任务和战斗照常进行。

## 3. 第一阶段

已知资源上做全局短程巡回：在最近候选间取最近邻起点，再用 2-opt 消除绕路；资源未知时按“新增可见格数 / 行走代价”
选择前沿探索。离线模拟器（与官方裁判差分测试：37 场有效官方场次逐帧完全一致）显示基线平均采集约 190/200；
已知全图的预言机也只有 194，剩余空间不足 1 分。尝试过把探索并入束搜索替代巡回，全部更差（187→154），已否决。

## 4. 第二阶段

- **寻路**：Dijkstra，未探索格视为可通行假设并加小代价；只有十字墙与爆炸会影响时间相关代价，其余情况按地形缓存距离表，
  并预计算邻居。改动前后决策逐字段一致，资源密集图规划 p99 由 84 ms 降至约 7 ms。
- **目标选择**：资源（按封顶前后的增量收益、可见对手竞速估计）、任务、事件机会（回血点、堡垒）以及**未探索区域的期望价值**
  （规则公布的资源数 ÷ 本场地图格数 × 平均价值 × 计分系数，开局有效，Tick 150 前线性衰减）共同进入有限宽度/深度的束搜索。
- **战斗**：攻击先于移动结算；按 v1.1 算术估计攻击、防御、移动、等待的收益，包括击杀平分奖励、死亡扣 60、易伤与反伤；
  看不见的对手不作为当前伤害真值。
- **决策类型**：balanced / collect / combat / survive，赛前登记，现场仅可经批准切换 `decision_type`。

## 5. LLM 与随机事件

- Prompt 只给本队合法感知、任务与公开公告；要求输出带绝对 Tick、坐标与参数的 JSON 事件列表，多点位逐个列出。
- 模型输出按事件逐条校验（种类、时间区间、坐标范围、参数白名单）；合格事件保留，不合格事件记录原因并允许有限重试。
- 新公告不受旧失败的退避影响；同一公告的重试仍退避，单席位始终只有一个在途请求，符合网关并发与配额规则。
- 无事件公告时每场仍至少调用一次（任务说明），满足任务分的 AI 资格要求。
- 真实 LLM 对照（24×24、500 ms、标准事件）：事件在生效前被完整理解的比例由 62% 提升到 78%（20 对，p = 0.025），
  非劣效复测 67% → 87%（52 对，p < 0.0001），得分不劣（+1.11，95% 区间 −0.61～+2.83）。

## 6. 鲁棒性

- 严格比赛启动器：不默认 ROS 域；令牌只绑定首个场次，换场后须重启；不读取系统代理、不跟随重定向、不记录令牌。
- 中途重启按感知恢复（实测：重启后同场 Tick 81 恢复，原进程接收新场 Tick 0）；最终帧不再发布动作。
- 第二阶段 500 ms 节奏下所有确认实验规划超时 0 次；规划 p99 约 6–8 ms，最大约 20 ms（单进程）。

## 7. 验证方法

- 自建训练平台调用**未修改的官方练习裁判**，4 组并行（每组独立 ROS 域对、端口与 CPU 核），自动开局、自动重试，约 55–220 场/小时。
- 配对设计：同场景、同关注席位、同对手，基线与候选各跑一次；对手一半为官方陪练车、一半为自有三种风格。
- 预先登记判定：名次 SPRT 与分差 mSPRT（每对后可检查而不抬高误报率，模拟验证 α=0.025 时误报 ≤ 0.019），确认性测试至少 24 对、
  任一质量排除即不通过；开发 / 验证 / 保留集分离，保留集只在最终版本上用一次。
- 比赛场景：规则尺寸地图，每场随机 5–8 个事件（标准数值，30% 按公告改写）、随机任务、四队均用真实 LLM、比赛启动器。
- 每次改代码运行回归：两套单元测试 + 9 条第二阶段回放 + 48 张第一阶段模拟图，决策须与基准版本逐字段一致。

## 8. 结果

| 改动 | 证据 | 结论 |
|---|---|---|
| 规划提速（缓存与快速路径） | 决策逐字段一致；p99 84 → 约 7 ms | 采用 |
| 未探索区域期望价值 | 24×24 全新地图 33 对 SPRT 接受，+5.59（+2.44～+8.74） | 采用 |
| AI 时序与逐事件校验 | 见第 5 节 | 采用 |
| 延后战斗、幻影资源衰减、延后到达任务、活锁打破、第一阶段探索 | 无效果、方向为负或未通过预设标准 | 否决并删除 |
| 生存权重 ×1.6/×2.5、任务权重 ×2 | 前两者全负（约 −14 分，几乎不再攻击）；后者 96 对 −0.46 | 否决并删除 |
| 近战一步前瞻、在线对手建模、残局伤害缓冲 | 200 ms 筛选三者均为 0 附近（−0.10～+0.08），名次 SPRT 接受"不更好" | 否决并删除 |
| 开局：推迟到达任务、远处探索按距离折扣 | 开局专项官方测试（裁判第 150 Tick 停止）均无可测提升 | 否决并删除 |

**失分取证**（读取裁判逐 Tick 全量帧，逐个资源归属拾取者）：资源池第 25 Tick 已被拾取 70%、第 50 Tick 90%；战斗分 14.0/15 已近饱和；
未进前二的比赛几乎都是开局资源少（31 对正常 75）。**上限测试**：给程序开局即知道全部资源位置的测试版本（仅实验室使用，绝不提交），
对会反应的对手资源差 −0.6 ± 5.4——完美信息也没有带来提升，开局剩余失分在结构上属于离对手更近的资源。

**对手联赛与稳健性**：8 组阵容（自博弈、官方车、当前三种风格、实验室脚本车猎手/抢点/龟缩及其组合），四队与三队小组（三队图由官方校验器校验）。
未发现被克制的打法；对"抢点车"扩大到 96 组独立比赛复核：前二率四队 0.73（随机 0.50）、三队 0.66（随机 0.67），不低于抢点车坐同一席位的对照。

**冻结版本 freeze-1030**：删除全部未采用开关，决策与保留集检查版本逐项一致；AI 按参赛手册使用 deepseek-flash、max_tokens 512（比赛条件真实模型实测 1 场 19 次调用无截断，回执 500/500），请求中加入 `"thinking": {"type": "disabled"}`（正式网关除 model 外原样转发，DeepSeek 默认开启思考；练习网关此前一直代为关闭；仿正式网关原样转发复核：不关闭时模型延迟中位 3.8 s、3 场 14 次 6 s 超时，关闭后中位 1.5 s、超时 3 次、可用计划约翻倍），此前比赛条件真实模型冒烟 6 场回执 500/500；地图边长上限按官方编辑器放宽到 200（此前 >128 会拒收全部感知）。按规则 v1.2 提交代码仓库与语雀技术报告，不提交镜像（容器方式曾通过整场冒烟，同机须 `--ipc host --user`）。

**最终保留集检查（比赛场景，唯一一次）**：最终版本对接手时的基线，25 对，分差 **+4.44（+1.89～+7.00）**，
对官方陪练车 +2.59、对自有对手 +6.45；事件按时理解 75% → 90%，死亡 170 → 139，质量排除 0。

## 9. 局限与待现场确认

- 对手为官方陪练车、自有程序与实验室脚本车，其他队伍的真实策略未知；练习地图与事件由本地生成，不代表正式安排。
- 正式模型统一为 deepseek-flash（关闭思考约 0.78–0.99 s），与练习调用同型号；事件理解率仍需在联调时复核；现场有线网络与比赛设备须在检录时验证。
- 若正式网关拒绝 `thinking` 或 `response_format` 字段（400/422），程序会依次去掉这两个可选字段后重试，保证至少能成功调用。
- 三队小组中若对手不交战，我方伤害常攒不到 500 封顶，优势降到随机水平（不低于随机）。
- 练习中的 AI 成功调用不构成正式资格，以裁判记录为准。
